# Environment Variables

On Serverless platforms (Cloudflare / Vercel / EdgeOne), environment variables are configured in the platform console or GitHub Secrets; self-hosted deployments use a `.env` file. The project has no `.env.example` — use the `.env` format below as the reference.

## Core Configuration (all platforms)

| Variable | Description | Required | Default |
|----------|-------------|----------|---------|
| `DB_TYPE` | Database type: `d1` / `tidb` / `mysql` / `mariadb` / `pg` / `hyperdrive` | Yes | `d1` (**Cloudflare only**; Vercel/EdgeOne/Docker/Node must explicitly set `tidb`/`mysql`/`mariadb`/`pg`; `hyperdrive` is Cloudflare-only, PostgreSQL accelerated via Hyperdrive connection pooling) |
| `DATABASE_URL` | Database connection string (not needed for `d1`) | Required for `tidb`/`mysql`/`mariadb`/`pg` | — |
| `ADMIN_USERNAME` | Admin login username | Yes | None |
| `ADMIN_PASSWORD` | Admin login password | Yes | None |
| `JWT_SECRET` | Login signing secret, at least 32 chars | Yes | None (auto-generated by the Cloudflare CI; set it manually on other platforms) |
| `TRUSTED_PROXY_IPS` | Comma-separated IP list of trusted reverse proxies/gateways (**exact IPs only, IPv6 supported, no CIDR/wildcards**). **Required when deployed behind a CDN or reverse proxy**: login rate limiting relies on it to recover the real client IP — `X-Forwarded-For` is only trusted when the TCP peer is on this list (the rightmost untrusted entry is used), otherwise the peer address is used, preventing forged-XFF bypass. **When unset**: direct deployments are keyed by the client address; behind a CDN/reverse proxy every user shares the gateway's rate-limit bucket — 5 consecutive failures by one attacker lock out all logins for 30 minutes | No | Empty (direct deployment) |
| `TRUSTED_IP_HEADER` | Custom trusted request-header name (e.g. `X-Real-IP`, `X-Client-IP`, or any custom header your gateway injects). **Set it when your reverse proxy/gateway forcibly overwrites a specific request header with the real client IP (clients cannot forge it)**: once set, that header takes top priority (ahead of the `DEPLOY_PLATFORM` platform schemes and the `TRUSTED_PROXY_IPS` chain), and login rate limiting plus audit logs use its value directly; when the header is missing or empty, it falls back to the platform scheme. **Only configure it when you are sure the upstream overwrites that header** — otherwise attackers can forge it to bypass rate limiting | No | Empty |
| `CSRF_ALLOWED_ORIGINS` | Origin-domain whitelist (comma-separated; domain only, no scheme or port). **Configure when a CDN pulls from your origin with the origin's own domain as the Host, so the origin sees a different Host than the domain browsers use — login and other write operations then get rejected by the origin check**: put the domain browsers actually visit. When unset, the default check applies (origin must match the Host the origin receives); direct deployments do not need it | No | Empty |
| `DEPLOY_PLATFORM` | Deployment platform identifier: `edgeone` / `vercel` / `docker` / `cf`. For EdgeOne and Vercel deployments, set the matching value in the platform console's environment variables (used to recover the real client IP); Docker images already set `docker` and Cloudflare builds inject `cf` automatically — no manual setup needed. **Never set `edgeone` or `vercel` on any other platform, or login rate limiting can be bypassed with forged request headers** | No | Empty (direct deployment; `docker` built into the Docker images) |
| `NODE_NAME` | Node name: set it when deploying multiple instances of the same project (e.g., multiple origin servers behind a CDN) to tell which instance handled a request in the request logs. Control characters, commas and quotes are removed automatically, and overlong names are truncated (max 10 CJK chars / 20 ASCII chars). When unset, falls back to the deployment platform name (EdgeOne/Vercel/Docker/Cloudflare, or `local` when none is set) | No | Deployment platform name |
| `UPSTREAM_PROXY_DISABLED` | Device-level outbound proxy disable (**affects only the current deployment instance**, no DB writes, shared config untouched — with one database shared across devices, this lets you turn the proxy off on a single device): `all` = disable entirely — requests go direct, pull and health checks (including manual ones in the admin UI) are skipped; `health` = disable only scheduled health checks — the in-container scheduler and `/api/cron/proxy-health` skip them, while the manual "Check now" button in the admin UI still works. Unset = normal | No | Empty |

::: tip
Not needed on edge runtimes without a TCP peer (e.g. Cloudflare Pages/Workers) — the edge-injected `CF-Connecting-IP` is used automatically; deployments with a TCP peer (direct Node / self-hosted reverse proxy / CDN origin) configure it as in the table above
:::

::: warning
`DB_TYPE` must match your actual database: `tidb` takes a MySQL-protocol URL, `mysql` takes a `mysql://` URL, `mariadb` takes a `mariadb://` URL, `pg` takes a PostgreSQL-protocol URL
:::

## Service (self-hosted)

| Variable | Description | Default |
|----------|-------------|---------|
| `PORT` | Listening port | `3000` |
| `NODE_ENV` | Runtime environment | `production` |
| `ENVIRONMENT` | Environment flag: when `production`, the login cookie gets `Secure` and CSRF uses the strict branch; built into the Docker images as `production`, other platforms fall back to non-production when unset | `production` (Docker) |

## Cron Auth (required)

| Variable | Description |
|----------|-------------|
| `CRON_SECRET` | Access key for the scheduled-task endpoints (**required — `/api/cron/*` returns 403 when unset**); requests must carry `Authorization: Bearer <CRON_SECRET>` |

## Connection String Formats

**TiDB Cloud / MySQL**:

```
mysql://user:pass@gateway01.xxxx.prod.aws.tidbcloud.com:4000/dbname?sslaccept=accept_invalid_certs
```

**MariaDB / pure MySQL (mariadb driver)**:

```
mariadb://user:pass@host:port/dbname
```

**PostgreSQL**:

```
postgresql://user:pass@host:port/dbname
```

On hosts with less than 1GB RAM, append pool parameters to the URL: `?connection_limit=5&pool_timeout=10`
