# Environment Variables

On Serverless platforms (Cloudflare / Vercel / EdgeOne), environment variables are configured in the platform console or GitHub Secrets; self-hosted deployments use a `.env` file. The project has no `.env.example` — use the `.env` format below as the reference.

## Core Configuration (all platforms)

| Variable | Description | Required | Default |
|----------|-------------|----------|---------|
| `DB_TYPE` | Database type: `d1` / `tidb` / `mariadb` / `pg` | Yes | `d1` |
| `DATABASE_URL` | Database connection string (not needed for `d1`) | Required for `tidb`/`mariadb`/`pg` | — |
| `ADMIN_USERNAME` | Admin login username | Yes | None |
| `ADMIN_PASSWORD` | Admin login password | Yes | None |
| `JWT_SECRET` | Login signing secret, at least 32 chars | Yes | None (auto-generated by the Cloudflare CI; set it manually on other platforms) |

::: warning
`DB_TYPE` must match your actual database: `tidb` takes a MySQL-protocol URL, `mariadb` takes a `mariadb://` URL, `pg` takes a PostgreSQL-protocol URL
:::

## Service (self-hosted)

| Variable | Description | Default |
|----------|-------------|---------|
| `PORT` | Listening port | `3000` |
| `NODE_ENV` | Runtime environment | `production` |

## Cron Auth (optional)

| Variable | Description |
|----------|-------------|
| `CRON_SECRET` | Access key for the scheduled-task endpoints; requests must carry `Authorization: Bearer <CRON_SECRET>` when set |

## By Platform

### Cloudflare (push to deploy)

Configure in GitHub repository Secrets:

```env
DB_TYPE=d1
ADMIN_USERNAME=admin
ADMIN_PASSWORD=your-password
CLOUDFLARE_API_TOKEN=xxx
CLOUDFLARE_ACCOUNT_ID=xxx
```

> `ADMIN_USERNAME`, `ADMIN_PASSWORD`, and `JWT_SECRET` are written into Cloudflare automatically by the deploy script — no manual configuration in the Cloudflare console. For TiDB/PG, add `DB_TYPE` and `DATABASE_URL`.

### Vercel / EdgeOne

Vercel: Settings → Environment Variables; EdgeOne: Makers console runtime environment variables.

```env
DB_TYPE=tidb                        # or pg / mariadb — never d1
DATABASE_URL=mysql://user:pass@host:4000/dbname?sslaccept=accept_invalid_certs
ADMIN_USERNAME=admin
ADMIN_PASSWORD=your-password
JWT_SECRET=random-secret-32+chars
CRON_SECRET=random-secret           # optional
```

### Self-hosted (Node.js / Docker)

```env
DB_TYPE=pg                          # or tidb / mariadb
DATABASE_URL=postgresql://user:pass@host:port/dbname
ADMIN_USERNAME=admin
ADMIN_PASSWORD=your-password
JWT_SECRET=random-secret-32+chars
PORT=3000
NODE_ENV=production
CRON_SECRET=random-secret           # optional
```

## Connection String Formats

**TiDB Cloud / MySQL**:

```
mysql://user:pass@gateway01.xxxx.prod.aws.tidbcloud.com:4000/dbname?sslaccept=accept_invalid_certs
```

**MariaDB / pure MySQL (mariadb driver)**:

```
mariadb://user:pass@host:port/dbname
```

**PostgreSQL**:

```
postgresql://user:pass@host:port/dbname
```

On hosts with less than 1GB RAM, append pool parameters to the URL: `?connection_limit=5&pool_timeout=10`
