# 自动分流

## 什么是自动分流

自动分流是 FWP 的高级功能，可以根据请求特征自动选择最佳模型和平台。

## 工作原理

```
客户端请求 → 分析请求特征 → 选择最佳平台/模型 → 转发请求
```

## 分流策略

### 基于优先级

优先级数值越大，优先级越高：

```
平台A (priority=3) > 平台B (priority=2) > 平台C (priority=1)
```

### 基于权重

按权重比例分配请求：

```
平台A (weight=3) : 平台B (weight=2) : 平台C (weight=1)
= 50% : 33% : 17%
```

### 基于健康状态

- 优先使用 healthy 平台
- down 平台完全跳过（触发熔断）
- degraded 平台正常参与分配，但已累计失败计数，更接近熔断阈值

## 自动模型 ID

在「自动模型」页面可以生成自动模型 ID（格式 `fwp-auto-model-xxxxxxxxxxxxxxxx`），支持复制与重新生成。客户端请求时将 `model` 设为该 ID，FWP 会自动挑选最佳平台与未冻结的模型：

- 模型发现结果按模型 ID 去重展示，带来源标签（`manual` 手动添加 / `auto` 自动发现）
- 每个模型可用开关加入或移出自动路由池
- 失败模型临时冻结 3 分钟，避免反复失败

## 平台模型发现

FWP 定时（默认每 6 小时）自动发现各平台支持的模型：

1. 了解平台能力
2. 配置模型映射
3. 监控模型可用性

发现请求走 OpenAI 兼容的 `/models` 接口：OpenAI 兼容平台（`openai` / `azure` / `custom`）可正常发现；**Anthropic 类型平台暂不支持自动发现**（原生协议无 `/models` 端点）。

有关模型名称解析（精确匹配与通配符）与数据管理维护方式的说明见 [管理后台使用说明](/guide/usage)，定时任务的调度方式见 [部署指南](/deployment/) 与 [Cron 任务](/api/cron)。
