# 告警通知

将代理链路的关键异常推送到你自己的接收端，不必守着后台刷状态。

## 入口

管理后台「系统设置 → 告警通知」。

## 通道

通知以 **Webhook（POST JSON）** 形式发出，请求体结构统一：

```json
{ "event": "key_banned", "title": "...", "body": "...", "timestamp": 1756000000 }
```

常见推送服务均可直接对接——在通道地址里填对应服务的 Webhook URL 即可：

| 服务 | URL 示例 |
|------|----------|
| Telegram Bot | `https://api.telegram.org/bot<token>/sendMessage`（配合请求模板类中转更佳） |
| Bark | `https://api.day.app/<your-key>` |
| Server酱 | `https://sctapi.ftqq.com/<sendkey>.send` |

可配置多个通道，事件触发时全部并发发送；单个通道失败不影响其他通道与请求本身。

## 可订阅的事件

| 事件 | 默认 | 触发时机 |
|------|------|----------|
| API Key 被封禁 | 开 | 上游持续错误触发 Key 自动封禁（通知只含密钥指纹，不含明文） |
| 平台熔断 | 开 | 平台连续失败达到阈值进入熔断，或半开探测失败重回熔断 |
| 平台降级 | 关 | 平台出现失败但未达熔断阈值，进入降级状态 |
| 全平台不可用 | 开 | 某次请求找不到任何可用平台/Key，服务实质不可用 |
| Key 用量达 80% | 开 | 某个 API Key 的 Token 或调用次数达到配额的 80%（每个 Key 只提醒一次） |

## 防轰炸

同类事件有冷却窗口（默认 10 分钟，可调 1–1440 分钟）：窗口内重复触发不会重复推送。例如平台反复熔断/恢复时，你只会收到间隔超过冷却时间的通知。

## 安全说明

- 通知配置存储于数据库并纳入保护清单，只能通过本设置页修改
- 通知发送完全旁路：配置缺失、网络失败都不会影响代理请求本身
