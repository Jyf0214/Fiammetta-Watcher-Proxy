# 调试台与失败排查

## Playground 调试台

管理后台侧边栏「调试台」：不离开后台就能向任意模型发一条真实请求，验证平台配置是否可用。

- **模型**：下拉列出所有已启用平台发现的模型（支持搜索）
- **API Key**：选择以哪个 Key 的身份发送（默认最新活跃的 Key）
- **流式输出**：默认开启，逐字渲染并显示首字延迟、Token 用量与本次费用
- **停止**：流式过程中可随时中断

两点设计值得知道：

1. **密钥不经过浏览器**——所选 Key 的明文由服务端注入，页面上只出现 Key 名称
2. **走完整代理链路**——请求与真实业务请求完全同路径：路由、重试、限流、日志、成本记账全部生效，调试产生的用量会计入配额（审计日志中记为「调试台调用」）

::: warning 部署兼容性
调试台通过服务端回环调用本实例的 `/v1` 入口实现。个别 Serverless 平台可能禁止函数自调用 HTTP 请求，此时调试台会返回明确报错；Docker 与自托管部署不受影响。
:::

## 失败请求留痕

「请求日志」中每条**错误记录**末尾有「查看」入口，弹窗展示：

| 字段 | 内容 |
|------|------|
| 请求体 | 下游发给代理的原始 JSON（截断至 16KB） |
| 响应片段 | 上游返回的错误响应原文（截断至 16KB） |

两者均可一键复制，用于在客户端或调试台复现问题。

### 覆盖范围

以下失败场景会写入留痕：

- 上游返回非 2xx 错误（含重试耗尽后的最终失败，OpenAI 与 Anthropic 协议均覆盖）
- 网络层失败（连接失败、DNS 错误等，无响应体时仅记录请求体）

成功请求不留痕。留痕数据跟随日志保留期（30 天），由日志归档任务同步清理。

### 使用流程建议

1. 在「请求日志」筛选错误记录，找到目标行点「查看」
2. 复制请求体，到「调试台」粘贴为用户消息内容（或用 curl 直接重放）
3. 结合响应片段判断是上游问题（鉴权/余额/参数）还是配置问题（模型名映射错误等）
