# 管理后台使用说明

FWP 管理后台分为 4 个功能区域：**概览**、**管理**、**监控**、**系统**。

## 仪表盘（概览）

仪表盘提供系统运行状态的全局视图，包括：

- **平台统计**: 活跃平台数
- **Key 统计**: 活跃 Key 数
- **请求统计**: 总请求数
- **Token 统计**: 总 Token 消耗量
- **性能指标**: 平均首 Token 时间（TTFT）、平均请求耗时
- **趋势图表**: 详情视图中各统计卡的迷你趋势图（请求数、Token、TPS 三项；TTFT/耗时无逐时段数据不展示）

仪表盘默认每 30 秒自动刷新，也可手动点击刷新按钮。支持网格视图和详情视图两种模式。

## 平台管理

平台管理用于配置和管理上游 AI 服务提供商。

### 添加平台

点击「添加平台」，填写以下信息：

| 字段 | 说明 | 必填 |
|------|------|------|
| 平台名称 | 自定义标识名称 | 是 |
| Base URL | 平台 API 地址（如 `https://api.openai.com`） | 是 |
| API 密钥 | 认证密钥，可配置多个（一行一个），请求时轮询分摊 | 是 |
| 平台类型 | `openai` / `azure` / `custom` / `anthropic` | 是 |
| 优先级 | 数值越大优先级越高 | 否（默认 0） |
| 权重 | 负载均衡权重，数值越大分配越多 | 否（默认 1） |
| RPM 限制 | 每分钟最大请求数 | 否 |
| TPM 限制 | 每分钟最大 Token 数 | 否 |
| 透传请求头 | 需要转发给上游的下游请求头白名单（JSON 数组） | 否 |

平台类型决定上游协议：多数厂商的 OpenAI 兼容端点选 `openai`，Anthropic 原生协议（官方 Claude、GitHub Copilot 等）选 `anthropic`，详见「平台配置」。

### 高级设置

| 字段 | 说明 | 默认值 |
|------|------|--------|
| 透传请求头 | 需要转发给上游的下游请求头白名单（JSON 数组） | 空 |
| 注入 stream_options | 是否自动注入 `stream_options`（部分上游不支持该字段时关闭） | 开 |
| 平台白名单 | 开启后该平台收到 429 不会被封禁，仅临时降级 2 分钟（密钥错误计数自动禁用不受影响） | 关 |
| 覆盖 UA | 开启后用自定义 UA 值替换发送给上游的 User-Agent（需同时填写自定义 UA 才生效，优先级高于自定义请求头中的 UA） | 关 |
| 自定义 UA | 覆盖发送给上游的 User-Agent | 空 |
| 自定义请求头 | 发送给上游的额外请求头（JSON 对象，最多 20 条） | 空 |

### 健康检查与熔断

FWP 内置自动健康检查机制：

- **healthy**: 正常状态，正常接收请求
- **degraded**: 已累计失败计数、更接近熔断阈值的状态，正常参与分配
- **down**: 故障状态，触发熔断，不分配请求

**熔断规则**:
- 连续失败 5 次后触发熔断，状态变为 `down`（429/401/403/402 等可重试错误优先走密钥封禁与换台流程，不直接计入熔断失败；重试耗尽后仍失败才会计入）
- 熔断后进入 60 秒冷却期
- 冷却期结束后自动进入 `half-open` 状态，发送探测请求
- 探测成功则恢复为 `healthy`，失败则重新熔断

### 密钥轮询

平台可配置多个密钥（命名对象 JSON 数组），FWP 采用 Round-Robin 轮询策略，在可用密钥间均匀分配请求，避免单个密钥调用量过高。

密钥错误计数会累加并自动禁用：429 → +1、401 → +2、402 → +5，累计达 5 次自动禁用该密钥（触发 429 时同时封禁 5 分钟）。

密钥格式：

```json
[
  {"name": "密钥1", "key": "sk-xxx"},
  {"name": "密钥2", "key": "sk-yyy"}
]
```

## API Key 管理

API Key 是客户端访问 FWP 的凭证。

### 创建 API Key

点击「添加 Key」，填写以下信息：

| 字段 | 说明 | 必填 |
|------|------|------|
| 名称 | 自定义标识名称 | 是 |
| Token 额度 | 总 Token 使用上限 | 否（默认 0） |
| 调用次数限制 | 总调用次数上限 | 否（默认 0） |
| RPM 限制 | 每分钟请求数限制 | 否（默认 0） |
| TPM 限制 | 每分钟 Token 数限制 | 否（默认 0） |
| 重置周期 | `monthly` / `daily` / `never` | 否（默认 monthly） |
| 过期时间 | 到期后 Key 自动禁用 | 否 |

### 配额规则

- 额度值为 `0` 表示不设限制

### 自动重置

根据 `resetPeriod` 设置自动重置已用 Token 数：
- `monthly` — 每月 1 日凌晨重置
- `daily` — 每天凌晨重置
- `never` — 永不重置

### Key 状态

- **启用**: 正常接受请求
- **禁用**: 拒绝所有请求（返回 401）
- **过期**: 到达过期时间后请求被拒绝（返回 401）
- **超限**: Token 用量或调用次数达到上限后拒绝请求（返回 429）

## 模型映射

模型映射允许将客户端请求的模型名映射到实际调用的模型名（含 `*` 通配前缀匹配，如 `gpt-4*`）。模型映射**没有独立的管理页面**，通过「数据管理」页的导出/导入 JSON 维护：在导出的 `modelMaps` 数组中添加记录（`alias` / `targetModel` / `platformId`）后导入即可；导入时 `alias` 已存在的映射会被跳过。

### 配置映射

| 字段 | 说明 |
|------|------|
| 别名 (Alias) | 客户端请求的模型名 |
| 目标模型 (Target) | 实际转发到上游的模型名 |
| 平台 | 限定在特定平台生效（留空则由路由引擎自动选择） |

### 使用示例

| 别名 | 目标模型 | 平台 | 效果 |
|------|----------|------|------|
| `gpt-4` | `gpt-4o` | — | 所有平台生效 |
| `claude-3` | `claude-3-5-sonnet` | Anthropic 平台 | 仅 Anthropic 生效 |

### 使用场景

1. **模型升级**: 旧模型名映射到新模型（如 `gpt-4` -> `gpt-4o`）
2. **成本优化**: 将昂贵模型映射到性价比更高的模型
3. **兼容适配**: 客户端使用固定模型名，后端灵活切换

### 自动模型（Auto Model）

自动模型是 FWP 的高级路由功能：

1. 系统定时（默认每 6 小时；Cloudflare 由 Cron 调度，其他部署由外部定时调用 `/api/cron/model-fetch`，见 [Cron 任务](/api/cron)）自动发现各平台支持的模型列表
2. 在「自动模型」页面可以查看各平台的模型发现结果
3. 可以选择特定模型加入自动路由池
4. 系统自动生成一个自动模型 ID，客户端使用该 ID 时，FWP 会自动选择最佳平台和模型
5. 自动模型请求失败时会临时冻结 3 分钟，避免反复失败

::: warning
模型发现请求走 OpenAI 兼容的 `/models` 接口，**Anthropic 类型平台暂不支持自动发现**（原生协议无 `/models` 端点），需手动添加平台模型。
:::

## 用量监控

### 用量统计

用量统计页面提供多维度的数据分析：

**趋势图表**:
- 支持按月/按周/按天查看请求量和 Token 用量趋势
- 支持单日小时级粒度展示

**Key 用量标签页**:
- 按 API Key 维度查看请求量、Token 用量、平均 TTFT

**平台用量标签页**:
- 按平台维度查看请求分布、Token 消耗、性能对比

### 请求日志

记录每一次 API 请求的详细信息：

| 字段 | 说明 |
|------|------|
| API Key | 使用的 Key 名称 |
| 平台 | 转发到的平台名称 |
| 模型 | 请求的模型名 |
| 状态码 | HTTP 响应状态码 |
| Token 用量 | prompt + completion 总 Token 数 |
| TTFT | 首个 Token 时间（流式响应有效） |
| 耗时 | 请求总耗时 |
| 错误信息 | 失败时的错误详情 |

支持按日期范围、API Key、状态码（200/400/401/429/500/503）与错误/正常状态筛选。

### 日志归档

- 超过 30 天的详细请求日志自动聚合为每日统计数据
- 聚合维度：日期 + API Key + 模型（记录含所属平台信息），含请求数、错误数、各 Token 数与平均 TTFT/耗时/TPS
- 支持手动触发日志归档

### 审计日志

记录所有管理员操作，包括：
- 登录/登出
- 创建/更新/删除平台
- 创建/更新/删除 API Key
- 数据导入/导出

每条审计日志包含操作者、操作类型、操作详情、客户端 IP。

## 数据管理

### 数据导出

支持三种导出类型：
- **系统配置**: 平台、模型映射、配置项
- **业务数据**: API Keys、请求日志、每日统计、审计日志
- **全部数据**: 以上所有内容

导出文件为 JSON 格式。

### 数据导入

支持导入之前导出的 JSON 文件，用于：
- 迁移到新服务器
- 恢复备份数据
- 同步配置

导入采用**先预览后确认**流程：显示每个数据类型的条数与问题数（缺必填字段、重复唯一键、含脱敏值），确认后按依赖顺序导入。导入**只添加不删除**现有数据；每种类型有条数上限，超出需分批导入。导入时会显示每个数据类型的导入数量和跳过数量（含跳过原因）。
